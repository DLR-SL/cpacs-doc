# Decisions

Decisions taken after the specification was written, each with the reasoning
that produced it. The specification states what the system must do and why;
these files record how a particular question was settled once building started.

One file per decision, numbered, dated, and not edited afterwards. A decision
that no longer holds is superseded by a new file that says so, so the reasoning
behind the earlier choice stays readable — otherwise a later reader sees only
the outcome, assumes it was arbitrary, and reverses it.

Not recorded here: module layout, function signatures, field names, command
line flags. Those change with every refactoring and are read from the code.
